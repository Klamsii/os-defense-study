Команды для защиты

Assignment 7: практическое задание и шпаргалка по твоим частым вопросам.

Первые шесть блоков идут по заданию. Остальные — отдельные примеры для повторения, их не нужно выполнять подряд. Вместо тестовых имён подставляй нужного пользователя и группу.

1. Создать папку и файлы

sudo mkdir -p /home/projectX
sudo touch /home/projectX/report.txt /home/projectX/data.csv
ls -ld /home/projectX
ls -l /home/projectX

mkdir создаёт каталог, -p — также недостающих родителей. touch создаёт пустой файл или обновляет время существующего. ls -ld показывает сам каталог; ls -l — его содержимое. В задании написано /home/projectX: регистр букв важен.

2. Создать пользователя и группу

sudo groupadd projectgroup
sudo useradd -m team1
sudo usermod -aG projectgroup team1
id team1
getent passwd team1
getent group projectgroup

groupadd создаёт группу. useradd -m создаёт пользователя с домашней папкой. В usermod -aG группа пользователь сначала указывают группу, потом пользователя. -a добавляет, сохраняя другие дополнительные группы; -G — дополнительные группы. id показывает UID, основную и дополнительные группы. getent проверяет запись в выбранной базе. Если объекты уже созданы, повторять создание не нужно.

3. Назначить владельца и группу

sudo chown team1:projectgroup /home/projectX
sudo chown team1:projectgroup /home/projectX/report.txt /home/projectX/data.csv
ls -ld /home/projectX
ls -l /home/projectX

chown пользователь:группа путь меняет владельца и группу. chown team1 путь меняет только владельца; chown :projectgroup путь или chgrp projectgroup путь — только группу. Смена группы каталога не меняет автоматически группу уже существующих файлов внутри.

4. Выдать права 750

sudo chmod 750 /home/projectX
sudo chmod 750 /home/projectX/report.txt /home/projectX/data.csv
ls -ld /home/projectX
ls -l /home/projectX

750 = rwxr-x---: владелец получает rwx, группа r-x, остальные ничего. Именно такие права запрошены в дополнительных заданиях. Для обычных текстовых файлов выполнение обычно не нужно, но здесь воспроизводится требование задания. chmod меняет права, chown — владельца.

5. Символьный режим

sudo chmod u=rwx,g=rx,o= /home/projectX/report.txt
sudo chmod g+w /home/projectX/report.txt
ls -l /home/projectX/report.txt
sudo chmod 750 /home/projectX/report.txt

u — владелец, g — группа, o — остальные, a — все категории. + добавляет право, - убирает, = задаёт точно. g+w добавит группе запись: из 750 получится 770. Последняя команда возвращает 750.

6. Наследование группы — setgid

sudo chmod g+s /home/projectX
sudo -u team1 touch /home/projectX/new.txt
ls -ld /home/projectX
ls -l /home/projectX/new.txt

У папки появится s в блоке группы, например drwxr-s---. Новый файл получит группу projectgroup. Его права не обязаны быть 750: они определяются режимом создания и umask. Setgid наследует группу, а не все права. Убрать бит: sudo chmod g-s /home/projectX. Нужно писать g+s, не g*s.

7. Все файлы в папке или только один

sudo chmod g+r /home/projectX/report.txt
sudo chmod -R g+rX /home/projectX
sudo chgrp -R projectgroup /home/projectX

Первая команда меняет один файл. -R обходит каталог рекурсивно, включая сам каталог и вложенные объекты. Большая X добавляет выполнение каталогам и тем файлам, у которых уже есть хоть один x; поэтому обычные текстовые файлы не становятся исполняемыми. g+rX добавляет группе чтение и проход; для совместной записи используют g+rwX.

8. Проверить доступ от имени пользователя

id team1
sudo -u team1 test -r /home/projectX/report.txt && echo 'read: yes'
sudo -u team1 test -w /home/projectX/report.txt && echo 'write: yes'
sudo -u team1 test -x /home/projectX && echo 'directory access: yes'
sudo -u team1 ls -l /home/projectX

sudo -u team1 запускает команду от имени team1. test -r, -w, -x проверяют чтение, запись и выполнение/проход. && запускает echo только при успешной проверке. Отсутствие вывода echo означает, что проверка не прошла; для вывода причины попробуй открыть файл или каталог. Проверка через root может скрыть обычный запрет доступа.

9. Основная и дополнительная группы

sudo groupadd secondgroup
sudo usermod -aG secondgroup team1
sudo usermod -g secondgroup team1
id team1
sudo gpasswd -d team1 projectgroup
id team1

У пользователя одна основная группа и несколько дополнительных. -g меняет основную, -aG добавляет дополнительную. gpasswd -d пользователь группа удаляет из дополнительной группы; так нельзя удалить основную группу пользователя. Группы Linux не бывают «дочерними». Уже открытая сессия может сохранить старый набор групп: для проверки войди заново.

10. Переименовать группу и пользователя

sudo groupmod -n newgroup secondgroup
sudo usermod -l teammate team1
id teammate
getent group newgroup

groupmod -n новое старое меняет имя группы. usermod -l новое старое меняет логин, но не переносит домашнюю папку автоматически. Это отдельные примеры: после переименования в командах нужно использовать новые имена. Пользователь не должен выполнять процессы, мешающие изменению учётной записи.

11. Пароль и срок действия

sudo passwd team1
sudo passwd -S team1
sudo chage -l team1
sudo chage -M 90 -W 7 team1

passwd team1 просит ввести новый пароль; символы при вводе не показываются. passwd -S выводит состояние пароля. chage -l показывает сроки; -M 90 задаёт максимум 90 дней между сменами, -W 7 предупреждает за 7 дней. passwd -d удаляет пароль без запроса нового; -l блокирует пароль, -u снимает блокировку. Это не установка нового пароля.

12. Удалить тестовые записи

sudo userdel team1
getent passwd team1
sudo groupdel projectgroup
getent group projectgroup

userdel удаляет учётную запись, обычно сохраняя домашнюю папку. userdel -r дополнительно удаляет домашнюю папку и почтовый ящик. groupdel удаляет группу, но не её файлы; группу нельзя удалить, пока она основная для существующего пользователя. Пустой вывод getent обычно означает отсутствие записи. Эти команды выполняют после завершения учебной работы, когда тестовые объекты больше не нужны.
