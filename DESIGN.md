# Linux Study design

A study workspace for the Assignment 8 defense. The first screen answers: which question should I practise next, and can I explain its answer?

Direction: Achromatic ledger, seed 910435320, from the locally available design-taste-frontend skill. No redraws. Neutral chrome, Geist text, local font files, colour on answer feedback and the real progress bar.

Product face: Linux filesystem-shaped mark; the special-permission digits 4 / 2 / 1 form the reference beside the current question. The working element is an answer form with per-option explanations. Counts come from checked questions, not from merely opening an explanation.

The top bar and the content share a centred 1200px maximum width including 24px gutters. The main working grid has a flexible question and a 280px reference column with 24px between them. The phone stacks the question navigator, question and reference.

Data: all 10 existing questions and 36 answer explanations retained. No invented exam questions or sample progress. This is a verified-attempt study set, not the complete hidden NetAcad bank.

Review: desktop, tablet and phone screenshots checked. No page-level horizontal overflow; correct single/multiple selection, empty search, topic filtering, all explanations, six command topics and reload persistence checked in the browser. Browser QA uses the in-app browser in the background. The style checker reports no source FAILs; the punctuation WARN refers to meaningful Russian explanation text retained from the original material.

Tradeoffs: long original English questions may take several lines on a phone; preserving their wording matters more than a display-headline line limit. Commands remain readable as complete copyable blocks. No external imagery or decorative animation is needed for study.

Font: Geist, SIL Open Font License. Licence at assets/OFL-Geist.txt.

Final critique: the working question is the first large content block; the remaining count and progress derive from the same checked set. Three viewport widths preserve all content without page overflow. Command examples pair explanation and code on desktop and stack them on a phone. Product Design was subsequently confirmed installed and used for a screenshot-based review of entering practice, checking an answer and advancing. That review identified keyboard focus remaining on the bottom navigation button after advancing. The next question heading now receives programmatic focus; its original wording and layout remain intact.
